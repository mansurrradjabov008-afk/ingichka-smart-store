# PERMANENT PROJECT RULES (Telegram Sales Bot)

## ENGINEERING
1. **Existing Language & Framework**: Keep the existing language/framework (Python 3.10+, aiogram 3.x, SQLite, aiohttp). Never rewrite from scratch. Change only what the task needs. Do not break working features.
2. **Secrets Management**: Secrets (`BOT_TOKEN`, `GEMINI_API_KEY`, `GROQ_API_KEY`, `OPENAI_API_KEY`, `ADMIN_TELEGRAM_IDS`, `CHANNEL_ID`, `WEBHOOK_SECRET`) must ONLY be loaded from `.env` or system environment variables. Never hardcode credentials in code.
3. **Resilience & Safe Fallbacks**: Wrap every external call (LLM APIs, Telegram API, database/file I/O) in `try/except` with a strict timeout and a safe user-facing fallback. The bot must never crash, stall, or go silent under any circumstance.
4. **Atomic Data Writes**: Write data files atomically (write to a temporary file in the same directory, then rename/replace atomically). Use a thread/async lock for concurrent access.
5. **Structured Error Logging**: Log errors to `bot.log` with `chat_id` and a concise reason for auditability and debugging.

## ANTI-HALLUCINATION (Most Important)
6. **Tool-Grounded Facts**: The LLM never invents or decides facts. Prices, stock quantity, sizes, colors, discounts, totals, delivery terms, and payment info come ONLY from tools, SQLite database, or verified configuration.
7. **Deterministic Temperature**: Run all LLM calls with `temperature <= 0.2` (default: `0.1` or `0.0`) to enforce strictly factual and grounded output.
8. **Grounding Validator**: Before sending any reply generated by the LLM, deterministic code must validate that every mentioned price, size, and product name exists in the tool results of that turn. If validation fails, regenerate once with the grounding error feedback attached. If it fails again, fallback to: `"Aniqlashtirib, operator javob beradi"` and notify the admin.
9. **Missing Data Handling**: If data or setting is missing, the bot states that it does not know or will ask the store owner. It never guesses or fabricates information.
10. **Deterministic Money Math**: All financial math (totals, quantity multiplications, promo discounts, subtotal, delivery fees) is computed strictly in deterministic Python code, NEVER by the LLM.

## REPORTING
11. **Verification First**: Never conclude or say "done" without executing full test suites. At the end of every task, report:
    - Files changed
    - Tests run
    - Pass / Fail counts
    - Known limitations / assumptions
12. **Autonomous Safe Continuation**: If anything in the task is ambiguous, proactively choose the safest, most robust option, explicitly state the assumption in the report, and continue to completion without blocking the user.
